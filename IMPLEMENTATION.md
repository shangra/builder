# Реализация коробочного лаунчера

## Задача

Аналитика — не один репозиторий, а набор независимых модулей (pivot, spreadsheet, migrations, admin и другие). Для продажи нужна **коробка**: заказчик получает каталог и одной командой поднимает весь продукт. Состав поставки меняется — модули добавляют и убирают без правок кода лаунчера.

Сборку каждого модуля по отдельности и ручной запуск `npm start` в нескольких терминалах для этого не подходят.

Сначала решён **запуск**. Сборка артефактов (`build`) в коде есть как заготовка, в поставку коробки пока не входит.

## Почему так, а не иначе

**Конфиг, а не жёсткий список папок.** Состав продукта живёт в `box.config.json`. Новый модуль — новая запись в `modules`; исключение из поставки — `"enabled": false`. Лаунчер не знает про CMS/Flow/MDM, пока их нет в конфиге.

**Свой супервизор, не Docker Compose и не Turborepo.** Коробка стартует из корня через `npm start`, без обязательного Docker и без монорепозиторных toolchains. Модули уже отдельные npm-пакеты со своими `package.json`. Лаунчер только оркестрирует процессы.

**`start` не ставит зависимости.** В прод коробка приезжает уже выкачанной, с `node_modules`. Повторный `npm ci` на стенде заказчика ломает воспроизводимость и требует сеть. Поэтому:

- `npm start` — только запуск;
- `npm install` — отдельный шаг, если зависимостей ещё нет;
- нет `node_modules` при старте — явная ошибка, а не тихая установка.

**Три kind у модуля.** Migrations должны отработать и завершиться, pivot и фронты — жить, пока не нажмут Ctrl+C. Готовый фронтовый `dist` можно отдать встроенным статическим сервером без `webpack-dev-server`.

| kind | зачем |
| --- | --- |
| `oneshot` | миграции: дождаться кода 0, потом стартовать зависимые сервисы |
| `service` | долгий процесс, перезапуск при падении (`restart: on-failure`) |
| `static` | раздача папки сборки на порту, без npm-скрипта |

**Порядок через `dependsOn`.** Pivot не должен подниматься, пока не прошли migrations. Порядок считается топологической сортировкой, а не порядком строк в JSON.

**Нулевые npm-зависимости у лаунчера.** Его копируют в корень продукта. Node 18+ встроенного `child_process`, `http`, `fs` достаточно.

## Как устроено

```
npm start  →  bin/sreda-builder.js  →  src/cli.js
                                      ├ start / list / validate / install  → box.config.json
                                      └ build (заготовка)                  → builder.config.json
```

1. **cli** разбирает команду. Для коробки читает `box.config.json`, режет список через `--only` / `--skip`, проверяет что каталоги на месте.
2. **box.config.js** резолвит `path` относительно корня коробки (`--root` или каталог конфига, поле `root` — обычно `workspace`). Подмешивает `package.json` модуля: если `start` не задан, берёт `scripts.start` / `scripts.dev`.
3. **supervisor** поднимает модули по зависимостям. Oneshot ждёт завершения. Service держит процесс, пишет лог в `logs/<id>.log`, по желанию ждёт `ready.url`. Static поднимает HTTP на `port`. Ctrl+C гасит всё дерево процессов (на Windows — `taskkill /T`).
4. **install-box** отдельно обходит модули и делает `npm ci` или `npm install`.

Корень продукта: `--root`, иначе `BOX_ROOT`, иначе папка, где лежит `box.config.json`. Лаунчер можно держать внутри `project` или снаружи с `--root`.

## Что в коробке сейчас

Запись в конфиге задаёт поставку:

- `sreda-analytics-migrations` — oneshot, `optional` (нет папки — коробка всё равно стартует)
- `sreda-pivot` — service после migrations, порт 3391
- `sreda-analytics-spreadsheet-frontend` — service, порт 3380
- `frontend-adm` — service после pivot, порт 3372

Поля модуля: `path`, `start`, `kind`, `dependsOn`, `enabled`, `optional`, `port`, `restart`, `env` / `envFile`, для static — `dist`.

## Что сознательно отложено

Пайплайн сборки pivot (`core:collect` → rollup → obfuscate → boxednode) и CRACO-сборка фронтов описаны в `builder.config.json` и `src/runner.js`, но для коробочной поставки пока не используются. Сначала нужен один вход «уже собранное — запустить». Сборку в тот же конфиг модулей можно добавить той же моделью `steps`, не меняя супервизор.
